# Security, privacy and deployment boundary

**Intended deployment:** localhost demonstration and controlled evaluation only.

## Data lifecycle

- The browser requests microphone permission only when the user clicks Record.
- Uploaded bytes are read with a hard size cap, signature-checked and normalized to WAV.
- Original and converted files are kept in a temporary per-turn directory and destroyed on success, cancellation and exceptions.
- The server stores only bounded text history and up to 20 short notes per ephemeral session. This storage is in RAM, is not backed by a database, and expires after the configured TTL or server restart.
- No audio content, transcripts, provider responses or API keys are intentionally logged. Exceptions expose sanitized text.
- Synthetic sine waves are the only audio fixtures in the public tests. No private voices or cloned voices are included.

## Trust boundaries

Speech transcripts and chat history are **untrusted**. All tool calls must be on the hard-coded allowlist and pass Pydantic input validation. Arithmetic uses an AST with only +, -, *, / and bounded depth/range. Note creation also requires an explicit user-prefixed command. Subprocess commands are static executable lists with file paths generated by the server; **no shell interpolation**. Unknown tools receive 403. CORS is restricted by configuration; absent list means no cross-origin browser access.

The remote HTTPS LLM adapter is disabled by default. If enabled, transcribed text and prior bounded history go to the configured provider. The user/operator must review that provider's data retention, pricing, policy and consent requirements first.

## Known deployment gaps

This is **not a publicly hardened service**. No authentication or authorization for sessions exists; UUIDs are not a substitute for identity. No persistent distributed session store, IP-based throttling, streaming budget limits, anti-CSRF layer or per-user expenditure policy. A public-facing version must add authentication, strict content-length enforcement at reverse proxy, ingress timeouts, rate limits, telemetry hygiene, origin checks, abuse detection and per-user quotas. Any public provider usage requires cost budgets, alerting and explicit approval.

The current process performs at most one active turn per session but does not globally limit the number of concurrent sessions. Deploy only in a trusted local environment.

## Threat model notes

- Prompt injection from transcripts must not cause unsupported actions; the registry enforces this independently of model prompts.
- Malformed and silent audio is rejected. ffmpeg is a separate parser attack surface; keep it patched, constrained and non-root (Docker does not run as root).
- Unexpectedly long uploads are rejected before decoding, with a maximum converted duration.
- Session IDs and request IDs are UUIDs and must not be treated as public credentials.
- Cancellation is cooperative: a subprocess is terminated on cancellation, and temporary files are cleaned up.
- No secrets in CI or the repository. No auto deployment, no auto merge.
